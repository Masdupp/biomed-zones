# BioMed Zones API

> Generated by `npm run openapi:export -w @biomed/api` from the OpenAPI registry. The interactive
> reference is served at **/api/docs** (Swagger UI) and the machine-readable document at
> **/api/openapi.json**; a copy is committed in [API/openapi.json](API/openapi.json).

Base URL through the gateway: `http://localhost:8080/api`.

## Authentication

- `POST /auth/login` sets two httpOnly, SameSite=Strict cookies: `bz_access` (JWT, 15 min) and
  `bz_refresh` (opaque token, 7 days). API clients may send the access token as `Authorization: Bearer`.
- `POST /auth/refresh` rotates the refresh token; reusing an already-rotated token revokes the whole
  session family (theft detection). Refresh tokens are stored as SHA-256 hashes only.
- Passwords: Argon2id (m = 19 MiB, t = 2, p = 1), 12–128 characters.
- Roles: `CONTRIBUTOR` (default on registration) and `ADMIN`.
- State-changing requests from browsers must carry a whitelisted `Origin` (CORS_ORIGINS).
- Rate limits: 1,500 requests / 15 min per IP overall, 20 / 15 min on authentication, 120 / h on
  contribution writes and reference checks, 20 / min on PDF reports (HTTP 429 with RateLimit headers).

Demo accounts (seeded): `admin@biomed-zones.local` / `BioMedAdmin!2026` and
`contributor@biomed-zones.local` / `BioMedContrib!2026`.

## Errors

All errors are JSON: `{ "error": "<code>", "message": "...", "details": [...] }`. Validation errors
(400, code `validation_error`) list every invalid field as `{ path, message }`.

## Endpoints

### Contributions

| Method | Path | Access | Summary |
|---|---|---|---|
| `GET` | `/contributions` | public | List contributions (public: approved only; mine=true: own; admins: any status) |
| `POST` | `/contributions` | user | Create a contribution (draft, or submitted for review with submit=true) |
| `GET` | `/contributions/{id}` | public | One contribution (approved ones are public) |
| `PATCH` | `/contributions/{id}` | user | Edit a draft or a rejected contribution (a rejected one returns to draft) |
| `DELETE` | `/contributions/{id}` | user | Delete a contribution (author: not yet approved; admin: any) |
| `POST` | `/contributions/{id}/submit` | user | Submit a draft for review (requires ≥ 1 reference) |
| `POST` | `/contributions/references/check` | user | Check a reference (DOI via Crossref, URL via HTTP) before submitting |

### Admin

| Method | Path | Access | Summary |
|---|---|---|---|
| `GET` | `/admin/queue` | admin | Pending contributions with the model’s current view of the same cell (diff view) |
| `POST` | `/admin/validate` | admin | Approve or reject a pending contribution (audited) |
| `POST` | `/admin/retrain` | admin | Start an asynchronous model retraining (proxied to the ML service, audited) |
| `GET` | `/admin/retrain/{runId}` | admin | Status of a retraining job |
| `GET` | `/admin/audit` | admin | Audit log of administrative and account actions |
| `GET` | `/admin/stats` | admin | Contribution counts by status and the active model run |

### Auth

| Method | Path | Access | Summary |
|---|---|---|---|
| `POST` | `/auth/register` | public | Create a contributor account and open a session |
| `POST` | `/auth/login` | public | Log in (sets httpOnly access and refresh cookies) |
| `POST` | `/auth/refresh` | public | Rotate the refresh token and issue a new access token |
| `POST` | `/auth/logout` | public | Revoke the refresh token and clear cookies |
| `GET` | `/auth/me` | user | Current user |

### Cells

| Method | Path | Access | Summary |
|---|---|---|---|
| `GET` | `/cells` | public | Scores of one species over the H3 grid (compact H3 rows or GeoJSON), paginated and cached |
| `GET` | `/cells/{h3}` | public | Full profile of one cell: environment with provenance, and scores for every species |
| `GET` | `/compare` | public | Two to four cells side by side for one species (parameter fits for a radar chart + table) |

### System

| Method | Path | Access | Summary |
|---|---|---|---|
| `GET` | `/health/live` | public | Liveness check |
| `GET` | `/health` | public | Readiness check (database + ML service) |
| `GET` | `/stats` | public | Headline numbers with their provenance (home page) |

### Account (GDPR)

| Method | Path | Access | Summary |
|---|---|---|---|
| `GET` | `/me/export` | user | Download all personal data held about the current user (GDPR art. 15 and 20) |
| `DELETE` | `/me` | user | Delete the current account (GDPR art. 17) |

### Reports

| Method | Path | Access | Summary |
|---|---|---|---|
| `GET` | `/reports/{h3}/{species}` | public | PDF report: score decomposition, SHAP drivers, environmental values with provenance |

### Sources

| Method | Path | Access | Summary |
|---|---|---|---|
| `GET` | `/sources` | public | Provenance registry: every data source with licence, retrieval date and usage |
| `GET` | `/sources/{id}` | public | One provenance record |
| `GET` | `/features` | public | Feature dictionary (label, unit, domain, definition) |

### Species

| Method | Path | Access | Summary |
|---|---|---|---|
| `GET` | `/species` | public | The nine species with headline facts, model metrics and score distribution |
| `GET` | `/species/{id}` | public | Full species profile: taxonomy, medical uses, tolerance bands, references, model metrics |
| `GET` | `/species/{id}/occurrences` | public | Occurrence points (GBIF / OBIS) as GeoJSON, thinned to one per 0.05° square |
